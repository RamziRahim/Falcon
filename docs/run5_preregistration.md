## What run #5 is

Run #4 re-run with honest pricing (PR #6, `docs/known_data_issues.md` item 10):

- fills at the next trading day's open; signals whose open is already past the target or
  below the stop are not traded
- `categorize()` measures entry and reward:risk from the close (stretched breakouts fail
  the RR floor)
- same universe, same frozen model (`ACTIVE_MODEL_VERSION`), same window
  (2024-08-14 to 2026-08-14), same 5-slot, 1%-risk policy
- output: `data/backtest_results_run5_honest_fills.csv`

The calibrated model was fitted on labels measured with the old pivot fills, so run #5
is an honest measurement of the system as it exists today, not of a re-fitted one.

## How it is judged

`python tests/evaluate_backtest_run.py data/backtest_results_run5_honest_fills.csv`
(EXECUTE-only; daily mark-to-market ledger; gross exposure capped at 100%;
liquidity-aware costs). All six checks must pass to say "edge demonstrated":

| # | check | threshold |
|---|---|---|
| 1 | total return minus Nifty buy-and-hold, same window | >= 10 percentage points |
| 2 | mean net return per taken trade | t-stat >= 2 |
| 3 | daily alpha vs market + size + momentum (HAC) | t-stat >= 2 |
| 4 | profit concentration | top 3 trades < 50% of profit |
| 5 | stability | both halves of the window profitable after costs |
| 6 | fill realism | >= 99% of entries inside a traded day range |

Reference points already computed with this exact scorecard:

- run #4 as recorded: passes 1-5, **fails 6** (29.8% of entries were prices that traded)
- run #4's signals re-priced at next-day open: -3.1% total, fails 1-5, passes 6

## What happens next, decided now

- **All six pass:** edge demonstrated in-sample only (the model saw this period during
  fitting). Next step is the paper-trading harness, not real money.
- **Any fail:** "no demonstrated edge". The response is NOT to tweak thresholds,
  filters or parameters against this same window until something passes. Allowed next
  steps, in order:
  1. Exactly one pre-registered entry variant (below), judged by the same scorecard.
  2. Re-fit the model on honest run #5 labels using the existing tuning/validation split,
     judged on the validation half only.
  3. If both fail, treat the Leadership breakout strategy as unproven and redesign.

## The one pre-registered entry variant (B: retracement)

- Breakouts whose close is within 3% of the pivot: buy at the next open (as run #5).
- Breakouts more than 3% above the pivot: a limit buy at the pivot, valid for 5 trading
  days. Fills only if a later day's low reaches the limit (at the limit, or the open if
  it gaps below). Cancelled if the stop level trades first or the order expires.
- Same stop/target levels, same scorecard, same window. No other variants or
  parameter values will be tried on this window.

### 2026-11-01: how variant B is implemented (interpretation of the rules, fixed before running it)

Code: `config.ENTRY_RETRACEMENT`, `RETRACEMENT_EXTENSION_PCT = 3.0`,
`RETRACEMENT_LIMIT_VALID_DAYS = 5`; `leadership_decision_engine.choose_entry_order()`;
`outcome_measurement._measure_limit_order_outcome()`; output
`data/backtest_results_run6_variant_b_retracement.csv`.

- **"More than 3% above the pivot"** means signal-day close > pivot × 1.03. Only plans
  whose stop/target levels are anchored on the pivot (stop below the pivot) become limit
  orders. A plan priced from the close (no usable proximal low) stays a next-open order.
- **Reward:risk for a limit order** is measured from the pivot, the price the order would
  pay. So stretched breakouts are no longer pushed below the RR floor by the run-up.
  Every other part of categorize() is unchanged.
- **Order handling** for each of the 5 days after the signal:
  - open ≤ stop → cancelled ("stop traded first");
  - open ≤ limit → filled at the open;
  - low ≤ limit → filled at the limit;
  - otherwise the order expires.
- **Fill day, conservatively:**
  - after an intraday fill at the limit, the day's high may have come first, so the
    target is not counted that day; the stop is;
  - after a gapped-open fill, stop then target count as usual.
  - The time stop counts the fill day as day 1.
- **Record and scorecard compatibility:**
  - `entry_date` is the trading day before the fill, so the MTM ledger opens the position
    on the real fill day and the scorecard's fill-realism check looks at the fill day.
  - `signal_date` keeps the original signal date.
  - The scorecard script is not changed.
- **Pending limit orders don't reserve capital or a slot** in the ledger. This is slightly
  optimistic: in practice an order resting for up to 5 days ties up margin.
- **AVOID's hypothetical trades** still use next-open fills. The scorecard is
  EXECUTE-only, so this doesn't affect the verdict.
